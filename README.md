# Wack-OS

Карманное модульное устройство в стиле Flipper Zero: master (ESP32-S3,
экран+энкодер) рисует интерфейс, сменный slave выполняет логику. Связь —
текстовый UART-протокол, специально не привязанный к конкретному железу.

Подробности:

- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — архитектура, роли,
  почему протокол важнее реализации.
- [`docs/PROTOCOL.md`](docs/PROTOCOL.md) — формат кадров, команды,
  коды ошибок, тайм-ауты.
- [`docs/UI.md`](docs/UI.md) — интерфейс: экраны, навигация, темы,
  Астольфо как состояние системы.

## Структура репозитория

```
components/wackos_protocol/   общий слой протокола (master и slave используют один и тот же код)
components/wackos_gfx/        рендер: кадровый буфер, примитивы, растровый шрифт (без привязки к железу)
master/                       проект ESP-IDF для ESP32-S3 (экран + энкодер)
master/main/screens/          по файлу на экран интерфейса
slave/                        проект ESP-IDF для ESP32 (диспетчер команд + заглушки модулей)
sim/                          симулятор экрана master для ноутбука (gcc + X11, без ESP-IDF)
tools/gen_font.py             генератор растрового шрифта из TTF
docs/                         документация
```

`master/` и `slave/` — два независимых ESP-IDF проекта (у каждого своя
прошивка, каждый открывается/собирается в Espressif-IDE отдельно).

## Симулятор на ноутбуке

Пока платы master нет на столе, интерфейс гоняется в окне:

```
cd sim && make && ./wackos-sim
```

Нужны только gcc и libX11, ESP-IDF не требуется. Подменены нижние слои
(экран, энкодер, звук, транспорт) — весь интерфейс, протокол и диспетчер
slave в симуляторе настоящие, те же файлы уедут в прошивку. Подробности
и управление — [`sim/README.md`](sim/README.md).

`make shots` там же снимает все экраны в файлы без окна, `make sheet` —
лист настроений Астольфо.

Если slave подключён по USB, симулятор говорит с живой платой:
`./wackos-sim -p /dev/ttyUSB0`, а `make test PORT=/dev/ttyUSB0` гоняет
по ней набор проверок протокола и интерфейса.

## Сборка в Espressif-IDE

1. File → Import → Existing IDF Project, указать `master/` или `slave/`
   как корень проекта.
2. Убедиться, что таргет выставлен верно (`idf.py set-target esp32s3`
   для master, `idf.py set-target esp32` для slave).
3. Build как обычно. `EXTRA_COMPONENT_DIRS` в CMakeLists.txt каждого
   проекта уже указывает на `../components`, так что `wackos_protocol`
   подтянется автоматически.

## Состояние проверок

Прогон `sim/`: `make test` (фальшивый slave) — 32 из 32; `make test
PORT=/dev/ttyUSB0` по живой плате ESP32 — те же проверки, кроме одной:
плата отвечает на запросы к чужому адресу. В исходниках это уже
исправлено (`wackos_proto_set_address()`), но на плате прошивка старая —
проверка позеленеет после перепрошивки `slave/`.

## Текущее состояние

Это каркас — есть только заглушки, реального железа под рукой сейчас
только плата master, поэтому код **не прогонялся на плате** и не
проверялся `idf.py build` (нет установленного ESP-IDF в этом окружении).
Перед первой прошивкой:

- Свериться с распиновкой энкодера в `master/main/board_pins.h` —
  пины `PIN_ENC_CLK/DT/SW` условные, задайте свои.
- Свериться с распиновкой UART в `master/main/board_pins.h` и
  `slave/main/board_pins.h` — они должны быть перекрёстно соединены
  (TX одной платы → RX другой).
- Проверить, что поля `esp_lcd_panel_dev_config_t` в
  `master/main/display.c` соответствуют версии ESP-IDF, установленной
  в вашем Espressif-IDE (это API у esp_lcd менялось между релизами,
  комментарий в коде отмечает это место).
- Интерфейс (экраны, персонаж, темы — см. [`docs/UI.md`](docs/UI.md))
  рисуется целиком в кадровый буфер (`components/wackos_gfx`) и
  выводится одним `display_flush()` — проверен в симуляторе, но на
  живом ST7789 ещё не крутился. Если картинка съедет вбок, смотрите
  `LCD_X_OFFSET` в `master/main/display.c` (у матриц 172x320 обычно
  нужен сдвиг 34 пикселя).

## Что дальше (не входит в этот каркас)

- Реальные модули на slave (`modules/module_radio.c` и т.п.) вместо
  заглушек `E_NOT_SUPPORTED`.
- Настройки в NVS (сейчас живут только в ОЗУ).
- Экран длинных операций (`RES OK ACCEPTED` + поток `EVT`).
- Пищалка: слой звука готов, нужен только пин в `board_pins.h`.
- При необходимости — переход на шину с несколькими slave (адрес `00`
  под broadcast уже зарезервирован в протоколе).
